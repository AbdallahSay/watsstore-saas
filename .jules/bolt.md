## 2024-05-18 - Bulk delete performance issue and Entity Framework Core 7+ optimizations
**Learning:** Using `.ExecuteDeleteAsync()` instead of `.RemoveRange()` for mass deletion prevents Entity Framework from loading thousands of records into memory just to delete them, solving Cartesian explosion and out-of-memory errors on large collections. However, because `.ExecuteDeleteAsync()` executes immediately and independently on the database, chaining multiple `.ExecuteDeleteAsync()` statements bypasses the implicit transactional safety of a single `.SaveChangesAsync()`.
**Action:** When migrating from `.RemoveRange()` to `.ExecuteDeleteAsync()` across multiple related tables (like cascades), always explicitly wrap the calls in `using var transaction = await _db.Database.BeginTransactionAsync();` with a `try/catch` and `Commit/Rollback` to ensure atomicity.
